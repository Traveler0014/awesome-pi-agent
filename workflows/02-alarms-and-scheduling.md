# 02 · 定时与提醒（alarm 驱动的工作流）

## 背景

pi 是异步的：任务可能在后台跑、会话可能被关掉、用户可能暂时离开。pi-alarm 让 agent 能给自己/用户设提醒，把「人肉记着」变成「到点自动注入」。

## 三种用法

| 方式 | 命令/工具 | 适用 |
|---|---|---|
| 自然语言 | `/alarm-set` | 随口说「20 分钟后提醒我吃饭」 |
| 相对时间 | `alarm_wait(delay, message)` | agent 在长流程里给自己设检查点 |
| 绝对时间 | `alarm_set(at, message)` | 固定时刻（"2026-08-03T10:00:00+08:00"） |

## 时区坑（实测踩过）

绝对时间**必须带时区偏移**，裸的 `2026-08-03T10:00:00` 按 UTC 解析，本地用户会差 8 小时。

```text
1. 先调 alarm_now 拿当前时间与本地偏移（如 +08:00）；
2. 用该偏移构造绝对时间：2026-08-03T10:00:00+08:00；
3. 相对与绝对各测一遍，别只测一种。
```

## 可复制提示词

```text
用 alarm 工具做一次定时演练：
1. alarm_now 获取当前时间与本地偏移；
2. alarm_wait 设一个 5 秒后的相对提醒，验证触发；
3. alarm_set 设一个 1 分钟后的绝对提醒（带正确偏移），验证触发；
4. alarm_list 确认两条都在，alarm_cancel 清理。
```

## 延伸：定时 prompt（可选）

结合 `pi-schedule-prompt` 类插件（cron 表达式调度 prompt），可以把 pi 变成「心跳」：每天早上 9 点自动巡检、每周日自动生成周报。短期提醒用 alarm 就够了，长期 cron 留给系统层面。

## 注意

- 提醒消息要**自包含**（写清楚接下来做什么），触发时 agent 不需要回溯太多上下文。
- 演示/测试要真实触发：设一个短提醒等它到点，不要用脚本模拟。
